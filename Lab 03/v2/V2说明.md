# V2：在现有代码上启用 blocking 查询

此目录的 evcns.c 由 Lab 03 根目录的现有文件生成，根目录原文件不变。

## 更改位置与原因

- 启用原有邻居 MPI_Send / MPI_Recv 循环，逐个查询有效邻居，并补上通信计时。
- 原 V1 的 Isend / Irecv / Testall / Waitall 查询段落保留为注释。
- 新增 MSG_QUERY_GRANT=9 和 MSG_QUERY_DONE=10，均通过 MPI_COMM_WORLD 发送一个 int。
- 基站每轮依次授权各节点，任意时刻仅一个节点主动查询；其他节点的 T6 继续接收请求并回复，避免双方同时等待回复。
- 有拥堵报告时，当前节点先完整接收基站 C4，再发送 DONE；没有拥堵也必须发送 DONE。
- 基站完成一整轮后等待约 3 秒再开始下一轮。与 V1 各节点独立每约 3 秒检查不同，V2 每轮时长还包含所有节点依次处理的时间。
- 30 秒后不再授权，先等当前节点 DONE，再执行原有 TERMINATE 和 3.5/4 秒 drain。不会在仍有主动邻居查询时停掉回复节点。
- 旧的独立 C4 轮询段落、V3 实现及原 V1/V3 main 保留为注释；本目录的新 main 始终执行 V2，无需 v2 参数。

端口线程、随机更新、阈值 <=2、二维 mesh、报告结构、基站时钟、1.5 秒窗口、diamond scanning、全部等距离候选、日志格式与 Reduce 保留现有实现。旧 nested-loop 仍保持注释。

## CAAS 运行

将本目录的 evcns.c 与 run_evcns.slurm 上传到 CAAS 同一目录。

使用作业脚本：

```bash
sbatch run_evcns.slurm
```

已获得与原版本相同的分配（10 个 MPI 进程，每进程 7 CPU）时，可以手动执行：

```bash
mpicc -fopenmp -o evcns evcns.c
srun -n 10 ./evcns 3 3
```

只有编译成功才继续运行。启动输出应为：

```text
>>> Running Version 2: Scheduled Blocking Send/Recv <<<
```

完成后保存当前目录的 log.txt 和作业终端输出。下次运行会覆盖 log.txt。

脚本沿用原来的模块、分区与资源设置，增加编译或运行失败时立即退出，防止误用旧执行文件或误打印完成。

## 指标含义

- 本版 payload 通信使用 Send/Recv，Iprobe 仅检查消息是否到达。
- 基站与节点 comm_time 包含新增授权消息的相关 MPI 调用耗时。
- 为保持原日志统计定义，报告 Msgs/Msg Size 仍只统计邻居请求与回复；Total Communication Events 仍为这些报告中的邻居消息数加报告数，不包含新增 GRANT/DONE，也不包含所有其他消息。
- 这个 V2 引入了查询调度与串行化，因此性能比较应说明协议差异，不能把差异全部归因于 MPI_Send 与 MPI_Isend 的函数选择。

## 本地检查

使用本机 WSL/Open MPI，未代替 CAAS 实验。正常 3x3 使用交付源码的 30 秒配置；另在临时测试副本中缩短运行/等待时间，强制所有端口忙碌，将发送替换为 MPI_Ssend，检查 3x3、1x4、1x1 的 blocking 协议。测试修改不会写入本目录交付源码。
